# Аудит сложности и компактный вид: ТЗ и калькуляция в одном `.md`

> Вопрос перед коммитом (19.07.2026): мы пишем в Notatnyk и техзадания, и калькуляции.
> Не усложнили ли мы приложение планами? Как не перегрузить «ТЗ-часть», где переменные
> не нужны, а нужно **красиво наблюдать, свернуть лишнее и тапнуть чекбокс с телефона**?
>
> **Ответ в одном абзаце:** ядро осталось на уровне HTML-редактора — это факт в цифрах (§1),
> а не ощущение. Сложность плана лежит в изолируемых слоях (§2). «ТЗ vs калькуляция» не
> требует двух полей и никакого компромисса в формате — это один `.md` с **лестницей
> синтаксиса**, где за неиспользуемое не платят (§3). Компактность решается **сворачиванием
> на уровне отображения** — ноль нового синтаксиса, состояние вне файла (§4). Чтобы так и
> осталось — кодифицируем бюджеты сложности (§5). Коммитить можно.
>
> Связано: [[development-plan]], [[keep-it-lightweight]], [[notatnyk-storage-format]].

## 1. Цифры ядра (замер 19.07.2026)

| Файл | Строк | Что делает |
|---|---|---|
| `src/parser.js` | 454 | весь движок: разметка, калькулятор без eval, переменные, Σ/Итого, скрытие |
| `src/main.js` | 979 | UI: список, редактор, рендер, синк-скролл, поиск, чекбокс-клики |
| `src/i18n.js` | 127 | 3 языка |
| `src/styles.css` | 254 | вся вёрстка, включая мобильный брейкпоинт |
| **Всего** | **1 814** | ноль зависимостей фронта, ноль бандлера, статические файлы |

Для масштаба: это меньше одного файла jQuery. Парсер — чистая функция, один проход по
строкам, рендер мгновенный. **«По сути не сложнее HTML-редактора» — подтверждено.**
Клик по чекбоксу в рендере **уже** правит исходник (`main.js:263`, через `checkLineMap`
из движка) — «тапнуть чекбокс с телефона» существует, осталось довести тач-цели (Этап М).

(2) **UI-хром** — кнопки/панели/чипы множатся незаметно. Второй лечится бюджетами §5.

## 3. ТЗ vs калькуляция: не два поля, а лестница синтаксиса

Смотрим на живую заметку `book-club.md`: сверху `## Т.З.` — таблица, текст, цитата клиента,
**ни одной формулы**; ниже — калькуляция с переменными и `Итого`. Уже сегодня это работает
без всякого «режима», потому что:

1. **Парсер построчный.** Строка без формул = промах пары регэкспов → обычный HTML.
   ТЗ-часть **ничего не платит** за существование калькулятора — ни в скорости, ни в UX.
2. **Переменные — opt-in.** Нет `[имя] =` в заметке — переменных нет. Не нужно их
   «отключать для ТЗ» — они не существуют, пока не написаны.
3. **Лестница синтаксиса** (платишь сложностью только за то, что написал):

```
пустая заметка          = блокнот (заголовки, списки, чекбоксы, таблицы)
+ «= 1200 грн»          = калькулятор (Σ, Итого-сверка)
+ «[ставка] = 1200»     = смета с переменными и пересчётом
+ «[оплата] [депозит]»  = денежная петля (Принять/Оплатить)
```

**Вывод: компромисс в формате не нужен — формат уже прогрессивный.** «Как не усложнить
поле ТЗ» → никак его не трогать. Единственная реальная проблема — **отображение**: длинное
ТЗ + длинная калькуляция в одной заметке = простыня, особенно на телефоне. Решение — §4.

## 4. Компактный вид: сворачивание по требованию (решение)

### 4.1. Сворачивание секций по заголовкам — ноль нового синтаксиса
- Тап по заголовку `##`/`###` в рендере сворачивает всё до следующего заголовка того же
  или высшего уровня (паттерн Obsidian/Notion — привычен пользователю).
- **Свёрнутая калк-секция показывает деньги:** `▸ Газон и планировка · Итого: 116 100 грн`.
  Движок **уже** возвращает `stats.sections` — ничего не пересчитываем. Это и есть «красиво
  наблюдать»: видишь только итоги, детали раскрываешь по требованию.
- Свёрнутая ТЗ-таблица: `▸ Т.З. · 7 параметров`. Свёрнутый чеклист: `▸ Этапы работ · 1/4 ✓`
  (счётчики чекбоксов по секции — мелкое расширение `stats`).
- Скрытый блок `/* */`: всегда чип `🙈 внутренние расчёты (N строк)` — разворачивается тапом
  (себестоимость не мозолит глаза, но в одном тапе).

### 4.2. Состояние свёрнутости — строго вне `.md`
- Хранится в `config.json`: `folds: { noteId: [хеш-текста-заголовка, …] }`. Хеш заголовка
  стабильнее номера строки при правках выше по тексту.
- **Файл `.md` не мутируем ради UI** ([[notatnyk-storage-format]]): чистые diff'ы, Dropbox
  не разносит твои свёртки на другие устройства, формат не знает о сворачивании вообще.
- Эвристики первого открытия на телефоне (≤640px): таблицы > 4 рядов — свёрнуты; секции
  > 10 строк — свёрнуты (калк-секции — до строки `Итого`); десктоп — всё развёрнуто.
- «Развернуть всё» — одна кнопка в шапке рендера; длинный тап по заголовку — «свернуть все,
  кроме этой».

### 4.3. Правки с телефона — дособрать из готового
- Чекбокс-тап уже работает (§1) → довести тач-цели ≥ 44×44 (Этап М, уже в плане).
- Тап по строке рендера → симбиоз-холст с кареткой на этой строке (`data-line`-якоря уже
  проставлены движком; Э3.3 `caretRangeFromPoint`).
- Сценарий «глянул статус → тапнул „готово" → закрыл» — без клавиатуры вообще: свёрнутый
  вид + чекбоксы это дают.

## 5. Бюджеты сложности (guardrails — теперь это правила, не пожелания)

1. **`parser.js` — чистая функция, ноль зависимостей, один проход.** Потолок до конца
   плана: **~700 строк** (сейчас 454). Упёрлись — значит, тащим в движок чужую работу.
2. **Ни одной новой сущности формата.** Всё новое — это либо переменная `[имя] =`, либо
   ключевое слово `LOCALE`, либо UI-состояние вне `.md`. (Сворачивание тест прошло: ноль
   синтаксиса.)
3. **Бюджет хрома:** нижняя навигация ≤ 5 кнопок, тулбар ≤ 7. Новая кнопка **вытесняет**
   старую, а не встаёт рядом.
4. **«Тест HTML-редактора» на каждом релизе:** холодный старт < 1 с; рендер 500 строк
   < 16 мс; экспорт < 300 мс. Провалили — фичи стоп, чиним скорость.
5. **UI-состояние никогда не пишется в `.md`** (свёрнутость, курсор, скролл — только config).
6. **Морозилка — действующий закон:** фича мимо текущего этапа → в морозилку, не «быстренько
   рядом».

---

## 6. Что сознательно НЕ делаем

- **Отдельное «поле ТЗ» / вкладки «спека | смета»** — режимы и вкладки убивают лёгкость;
  лестница синтаксиса (§3) решает то же без них.
- **Синтаксис сворачивания в файле** (`<details>`, `##>` и т.п.) — UI-состояние в `.md` =
  мусор в diff'ах и конфликты синка.
- **Многоточие посреди абзаца** — сворачиваем только по границам секций/блоков/таблиц,
  иначе непредсказуемо.
- **WYSIWYG-прятание маркеров** — уже отложено (Э3.4): каретка в скрытых спанах — грабли.
