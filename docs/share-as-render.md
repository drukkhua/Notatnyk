# Share, Track & Accept — техническая схема отдачи сметы клиенту

> Как отдать клиенту **красивую смету, физически без формул и себестоимости**, увидеть, что
> он её **открыл**, дать ему **принять в 1 тап** или **оспорить-lite** («уберите газон»,
> «тираж 500») — и **уведомить автора**. Автор считает локально, делится ссылкой, по новым
> вводным перегенерирует смету одной кнопкой.
>
> **Переориентация (по [[market-analysis]] §3, §7).** Прошлая версия этой схемы решала
> «докажи, что рендер выведен из исходника» — красивая инженерия под задачу, которой у 95%
> клиентов нет. Та же крипта **перецелена в то, за что платят**: «клиент принял смету v3
> такого-то числа» + трекинг + уведомление. Тяжёлый аудит-стек (sealed source, хеш-цепочка,
> раскрытие по требованию) — **в морозилке до первых $2 000 MRR** (§11). Ведущий принцип —
> лёгкость ([[keep-it-lightweight]]): крипта берётся готовая, минимально, без своего велосипеда.

Статус: дизайн v2.1 (переписан 18.07.2026 под денежную петлю; в тот же день дополнен
корректировками K1–K4 из полевого исследования [[voice-of-customer]] — депозит при принятии,
выбор варианта, срок действия, напоминание). Опирается на модель Notatnyk (`.md`-first,
скрытые `//` и `/* */`, движок `src/parser.js`) и на [[development-plan]] (Этап 1 —
офлайн-lite, Этап 5 — мини-релей).

## 0. Словарь

| Термин | Что это |
|---|---|
| **Source (исходник)** | Обычная заметка `.md`: формулы, переменные, скрытая себестоимость. Единственный источник истины. Живёт локально. |
| **Render (рендер)** | Публичный результат: только то, что должен видеть клиент. Формул внутри нет — они **удалены, а не спрятаны**. |
| **Manifest** | Маленький JSON-паспорт: версия, время, хеш, подпись автора. |
| **Relay (релей)** | Минимальное облако (Pro): хостит render, логирует открытие, принимает «Принять/Оспорить», шлёт уведомление автору. **Исходник и формулы не хранит.** |
| **Accept-стамп** | Подписанная автором строка `id·version·#hash·дата` — доказуемый след «эту смету выпустил я». При принятии клиентом дополняется отметкой принятия. |
| **Оспорить-lite** | Структурированный запрос правки от клиента: снять позицию / сменить вводную / одна заметка. **Не чат, не CRM.** |

## 1. Главный принцип: разделение, а не сокрытие

Ошибка конкурентов и веб-калькуляторов — они **прячут** формулы (CSS `display:none`, скрытые
поля, JS-переменные). Всё это лежит в payload и достаётся из devtools за 10 секунд.

Notatnyk делает иначе: **на устройстве автора source компилируется в render, и в render
физически нет исходных формул**. Клиент получает документ, в котором нечего раскрывать —
ни в DOM, ни в JS, ни в сети. Это же обслуживает боль «не показать кухню/себестоимость»
([[market-analysis]] §4, боль #3) — и мы «скроем формулы и закупки, если так нужно».

```
        УСТРОЙСТВО АВТОРА (доверенная зона)         │   РЕЛЕЙ / КЛИЕНТ (недоверенная зона)
                                                    │
  source.md ──►  движок парсера  ──►  render.json   │
  (формулы,        (compute)          (только       │
   переменные,                        числа+текст,  │
   // скрытое)                        без формул) ───┼──►  https://ntk.app/r/<id>
        │                                           │         статичный рендер JSON.
        │                                           │     В payload — НИ ОДНОЙ формулы.
        │                                           │     Релей логирует «открыто»,
        └── (исходник НЕ покидает устройство ) ─────┼──   принимает «Принять/Оспорить».
                                                    │
```

Граница доверия — стрелка «в релей». Всё, что её пересекает к клиенту, уже обеззаражено.
**Исходник границу не пересекает вовсе** (в морозилке — опциональная зашифрованная копия для
аудита; сейчас не строим).

## 2. Модель данных исходника

Source остаётся **одним `.md`** ([[notatnyk-storage-format]]), без сайдкаров. Расширяем только
необязательным YAML-фронтматтером-кэшем последней публикации. Нет фронтматтера → заметка просто
не опубликована, всё как раньше.

```markdown
---
ntk:
  id: 9f3a1c                 # стабильный id (генерится при первой отдаче)
  author: ed25519:Ab12…9Zx   # публичный ключ автора
  version: 3                 # монотонный номер версии
  published_at: 2026-07-16T14:23:07+03:00
  hash: 7d1e44c0             # короткий хеш канонизированного render (§6)
  visibility:                # что попадает в render
    hide_comments: true      # строки // и блоки /* */ вырезаются (дефолт)
    hide_math_source: true   # показывать только результат, не выражение
    hide_unit_costs: false   # прятать ли строки валюта/шт
---
# Книжный клуб — закладки
> @Ирина
> Нужны премиальные закладки, софт-тач, тираж 4000.
[оплата] = https://buy.stripe.com/xxxx
[депозит] = 30%
[действительна до] = 14 дней
- печать = 18400/1200*1125 = грн
Итого: = грн [4000 шт]
```

Источник истины — **тело `.md`**. Фронтматтер `ntk:` производный, перегенерируется при каждой
отдаче, руками не редактируется.

### Уровни видимости (по возрастанию скрытности)
1. `// строка` и `/* блок */` — **уже есть**. Не в render, но считаются в Σ (себестоимость).
2. `hide_math_source` — в render только результат `17 250 грн`, не выражение `18400/1200*1125`.
3. Объявления переменных `[имя] = …` всегда режутся из render; подставляется значение.
   **Строковые** переменные (`[оплата]`, `[iban]`, `[срок]`, [[development-plan]] Э2.2) —
   значение подставляется как текст/кнопка, само объявление в render не уходит.

## 3. Render и почему он безопасен — allowlist-проекция

Render — **не HTML со спрятанными кусками**, а самостоятельный минимальный документ из
«разрешённых» узлов AST. Формат — `render.json` (компактный, легко кэшировать и подписывать):

```json
{
  "schema": "ntk-render/2",
  "id": "9f3a1c",
  "version": 3,
  "published_at": "2026-07-16T14:23:07+03:00",
  "title": "Книжный клуб — закладки",
  "blocks": [
    { "t": "quote", "text": "Нужны премиальные закладки, тираж 4000.", "client": "Ирина" },
    { "t": "li", "text": "печать (полиграфия)", "value": "17 250 грн" },
    { "t": "total", "label": "Итого", "value": "54 980 грн", "per_unit": "13,75 грн/шт",
      "option": 1, "option_label": "4000 шт" },
    { "t": "total", "value": "58 540 грн", "option": 2, "option_label": "5000 шт" },
    { "t": "pay", "label": "Оплатить", "url": "https://buy.stripe.com/xxxx",
      "deposit": "30%" }
  ],
  "valid_until": "2026-07-30",
  "author": "ed25519:Ab12…9Zx",
  "hash": "7d1e44c0",
  "sig": "ed25519:9aa2…",
  "app_link": "https://ntk.app"
}
```

Как строится (в `src/parser.js`, на устройстве автора):

```
parse(source.md)          → AST со ВСЕМИ узлами (формулы, // скрытое, переменные)
   │
compute(AST)              → значения (Σ, Итого, калькулятор, per-unit, переменные)
   │
project(AST, visibility)  → НОВОЕ дерево: только визуальные узлы и вычисленные значения;
   │                        узлы-формулы / скрытое / объявления переменных — ОТБРАСЫВАЕМ
render.json               → сериализация обеззараженного дерева
```

`project()` — ключевая функция безопасности. Правило: **в render.json попадает только явно
разрешённое (allowlist), а не «всё кроме скрытого» (denylist).** Незнакомый новый узел по
умолчанию не проходит — allowlist нельзя случайно «пробить» новым синтаксисом.

Гарантии клиенту: в `render.json` нет строк-выражений (только результаты), нет `//` / `/* */`,
нет объявлений переменных. Страница `ntk.app/r/<id>` — статический рендер этого JSON. Devtools
показывает ровно то, что видит глаз: числа и текст. Раскрывать нечего.

## 4. Как смета попадает к клиенту — два пути

### 4.1. Офлайн-файл — бесплатно ([[development-plan]] Э1.4)
Кнопка «Отдать клиенту» → PDF и самодостаточный `.html` (обёртка над `render.json`). Формул
внутри нет по построению (§3). Футер: `v3 · 16.07.2026 · #7d1e44c0` + ссылка на приложение
(растовой крючок). «Принять/Оспорить» — предзаполненный `mailto`/WhatsApp/Telegram (офлайн-lite).

### 4.2. Мини-релей — Pro ([[development-plan]] Э5)
```
Автор жмёт «Поделиться ссылкой»
   │
   ├─ compute() + project()  →  render.json     (санированный, публичный)
   ├─ build manifest         →  подпись автора над id·version·hash·дата
   │
   └─ PUT в объектное хранилище:
        r/<id>/v3/render.json     ← отдаётся клиенту (public read)
        r/<id>/latest → v3        ← указатель «текущая версия»
   →  ссылка: https://ntk.app/r/9f3a1c
```
Релей **не хранит** исходник и формулы. Он хостит render, ведёт лог событий (§7) и принимает
ответы клиента (§8). Idle-стоимость ~ноль (объектное хранилище + функции по событию).

### 4.3. Что уходит клиенту
| Артефакт | Клиент получает? | Содержит формулы? |
|---|---|---|
| `render.json` (числа, текст, кнопки) | ✅ да | ❌ нет (по построению) |
| подпись/хеш в manifest | ✅ да | ❌ нет |
| исходник `.md` | ❌ никогда | (не покидает устройство автора) |

## 5. Штамп версии и Accept-стамп

Футер публичной страницы и `.html` всегда показывает штамп:
```
────────────────────────────────
v3 · 16.07.2026 14:23 · #7d1e44c0 · ✔ выпущено Ab12…9Zx · действительна до 30.07
                                     [ Принять и внести депозит 30% ]  [ Оспорить ]
```
- **«Действительна до»** — из `[действительна до]` ([[voice-of-customer]] §4: стандарт 7–30
  дней; в стройке 10–21 — материалы дорожают внутри месяца). После даты страница показывает
  «Смета истекла — запросить обновление» (запрос v-next автору), а не молча принимает старую
  цену. Защита маржи + мягкая срочность.
- **Кнопка принятия** включает депозит, если задан `[депозит]` (§8.1).
- `v3` — номер версии; `16.07.2026 14:23` — `published_at`; `#7d1e44c0` — короткий хеш render.
- `✔ выпущено …` — Ed25519-подпись строки `id·version·hash·дата`. Это **Accept-стамп**:
  доказуемый след «эту смету выпустил владелец ключа». За это платят в споре «вы называли X»
  ([[market-analysis]] §4, боль #7), а не за «докажи вывод рендера».
- Дата — из момента публикации, не mtime (стабильна при синке между устройствами).

Крипта здесь **минимальна**: одна подпись + один хеш (`ed25519-dalek`, `blake3` — маленькие
проверенные крейты). Хеш-цепочка `prev_hash`, sealed source, публичная кнопка «Проверить
вывод рендера» — **в морозилке** (§11).

## 6. Хеширование (минимальное)

Хешируем не байты файла, а **канонизированный render.json** (без поля `sig`): нормализовать
`\n`, убрать трейлинг-пробелы. `hash = blake3(canonical(render.json without sig))`, короткий
префикс (8 hex) — в штамп. Этого достаточно, чтобы штамп был воспроизводим и стабилен.
Канонизация исходника, пин курсов валют, `source_hash` — в морозилке (нужны только для аудита).

## 7. Трекинг открытия (Pro) — [[development-plan]] Э5.2

Релей логирует событие «открыто» **без cookies/PII**: `{id, version, ts}` + счётчик. Автор
видит в приложении и в ленте `@клиента`: «Иванов открыл смету v3 — 2 раза, последний раз вчера».
Прокси-метрика интереса/доверия. Открыл, но не принял N дней → подсказка автору «напомнить».

## 8. «Принять» и «Оспорить-lite» — [[development-plan]] Э5.3

Ключевая денежная механика. **Без чата и CRM.**

### 8.1. Принять (1 тап) — и сразу депозит, и выбор варианта
Кнопка на странице → релей фиксирует принятие, привязанное к `id·version·#hash·дата`; при Pro —
дополняет Accept-стамп отметкой «принято клиентом, <время>». Автору — уведомление (§9). Клиент
исходник не получает, но получает математически связанный след «принято именно это, тогда-то».

- **K1. Депозит в момент «да».** Если задан `[депозит]`, кнопка — **«Принять и внести депозит
  $540»** (сумма считается движком от `Итого`); после тапа открывается платёжная ссылка мастера
  с суммой. Референс — «Approve & Pay Deposit» у Jobber. Инвойс с онлайн-ссылкой платится ×4
  быстрее; 87% Stripe-инвойсов — за 24 часа ([[voice-of-customer]] §2). Деньги идут напрямую
  мастеру, релей их не касается.
- **K2. Выбор варианта.** Несколько секций-`Итого` в заметке = варианты (`option` в render.json,
  §3) — клиент перед принятием выбирает: «Принял вариант 2 (5000 шт)». Депозит пересчитывается
  от выбранного `Итого`. Закрытие 42%→52%, чек +18–22% у дающих варианты ([[voice-of-customer]]
  §3). Движок уже умеет секции — новой сложности почти нет.

### 8.2. Оспорить-lite (структурировано, ровно 3 действия)
Клиент делает **одно** из:
1. **снять галочку с позиции** — «убрать газон на переднем участке» = снять строку газона;
2. **предложить новое значение вводной** — «сократить тираж до 500» = поменять `[тираж]` /
   `[4000 шт]` на 500 прямо в интерфейсе ссылки (вводные — это переменные исходника);
3. оставить **одну короткую заметку** (одно текстовое поле).

Релей передаёт автору **структурированный запрос**: `{ remove: ["газон передний"], set: {"тираж": 500}, note: "…" }`.

### 8.3. Пересчёт v4 в 1 тап
Автор видит запрос в приложении. Снятая позиция и новая вводная **уже применены к исходнику**:
- «сменить вводную» = правка одной переменной `[тираж] = 500` → движок пересчитывает мгновенно;
- «снять позицию» = строка помечается исключённой (или комментируется `//`) → уходит из render и из Σ.

Автор жмёт «Отправить обновление»: `version+1`, `compute() → project() → render.json`, `latest → v4`.
Клиент по старой ссылке видит v4 с новым штампом. **Сделка спасена, приложение не усложнилось** —
переиспользуем существующие позиции и `?`-вводные ([[development-plan]] Э2.3, Э5.3).

```
Ключевая выгода: вводные — это переменные в исходнике, поэтому перегенерация =
правка одной строки + кнопка, а не пересбор документа. Автор трогает только цифры.
```

## 9. Уведомления автору — [[development-plan]] Э5.4

При **открытии / принятии / споре** релей:
- шлёт **email автору** (managed-провайдер транзакционной почты, не свой SMTP — лёгкость);
- кладёт уведомление **внутрь приложения** (лента событий + бейдж на `@клиенте`).

Так автор узнаёт «клиент открыл / принял / просит правку» без опроса — петля до денег замыкается.

**K4. Напоминание в 1 тап (не автоворонка).** По сигналу «открыл, не принял N дней» /
«не открыл 3 дня» приложение подсказывает: «Иванов открыл 2 раза, не принял. Напомнить?» —
один тап шлёт предзаполненное сообщение в мессенджер (мессенджер, не email: открываемость
95–98% против ~20%, [[voice-of-customer]] §8). 80% контрактов закрываются со 2–5-го касания,
большинство мастеров сдаётся после первого ([[voice-of-customer]] §5). Одна кнопка — не CRM.

## 10. Личность автора (минимально)

- При первой отдаче генерится пара **Ed25519**. Приватный ключ — в системном хранилище
  (Keychain / Credential Manager / Keystore), не в `.md`.
- Публичный ключ = **author id**, светится в штампе. Подписывает Accept-стамп.
- **Локальная версия первична и бесплатна**; облако/подпись включаются только когда автор
  осознанно жмёт «Поделиться ссылкой».
- Перенос ключа на второе устройство (QR + Argon2id-обёртка), recovery-фраза — **в морозилке**
  (нужно только для мульти-устройства, не для цели).

## 11. Модель угроз и границы

| Клиент/злоумышленник хочет… | Результат |
|---|---|
| Открыть devtools и найти формулу | ❌ Их нет в payload. Только числа/текст/кнопки. |
| Подменить число в рендере и показать другому | ❌ `hash`/`sig` не сойдутся у того, кто проверит штамп. |
| Выдать чужой расчёт за расчёт автора | ❌ Нет приватного ключа автора — подпись не подделать. |
| Реверснуть формулу из чисел | ⚠️ Только угадать — это домысел, не утечка исходника. |
| Оспорить бесконечно (спам-правки) | ⚠️ Оспорить-lite = ровно 3 действия за версию; не чат. |

Схема **не** обещает: скрыть *результаты* (они по определению показаны) и защитить от автора,
который сам решил показать формулу. Мы защищаем исходник, не арифметику на виду.

## 12. Что строим сейчас vs морозилка

**Строим (по [[development-plan]]):**
- Этап 1 (офлайн, бесплатно): `project()` allowlist, экспорт PDF/`.html`, штамп
  `v·дата·#hash·действительна до`, подпись Accept-стампа, «Принять и внести депозит /
  Оспорить» через мессенджер, кнопка «Оплатить» из `[оплата]` + `[депозит]`.
- Этап 5 (мини-релей, Pro): ссылка `ntk.app/r/<id>`, трекинг открытия, онлайн «Принять и
  внести депозит» с выбором варианта, «Оспорить-lite», просрочка ссылки, пересчёт v4,
  уведомления email + в приложении, напоминание в 1 тап.

**Морозилка (после $2 000 MRR):** sealed source (`XChaCha20-Poly1305`) и аудит-раскрытие; хеш-цепочка
`prev_hash` и tamper-evident история; публичная кнопка «Проверить вывод рендера»; иммутабельные
облачные версии как юридический артефакт; свой E2E-sync исходников; пин курсов валют в снимок;
мульти-устройство с QR-переносом ключа; выбор «версия/актуальная» с юридической заморозкой.

### TL;DR
- Клиенту уходит **отдельно собранный обеззараженный render** (allowlist, §3) — формул в payload нет.
- Крипта **перецелена**: минимальная подпись+хеш = Accept-стамп «выпустил/принял», за это платят;
  тяжёлый аудит-стек — в морозилке (§12).
- **Принятие = деньги:** «Принять и внести депозит» одной кнопкой (`[депозит]`), выбор
  варианта из секций-`Итого` (`option`), срок действия `[действительна до]` — всё это
  переменные исходника, подтверждено болями из [[voice-of-customer]] (K1–K3).
- **Мини-релей (Pro)** даёт трекинг открытия, онлайн «Принять» в 1 тап, «Оспорить-lite» (снять
  позицию / сменить вводную / заметка) → **пересчёт v4 в 1 тап**, уведомление автору и
  напоминание в 1 тап (K4). Деньги мастера через нас не проходят.
- Локальная работа первична и бесплатна; облако/подпись — по кнопке «Поделиться».
