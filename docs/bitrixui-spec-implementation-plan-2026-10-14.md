# План переноса доработок Т.З. BitrixUI в Notatnyk

Дата: 14.10.2026. Основание: [аудит](bitrixui-spec-reuse-audit-2026-10-14.md).

Цель: реализовать все восемь предложенных доработок в Notatnyk с сохранением существующей грамматики, общего итога, локального файлового хранения, RU/UK/EN и мобильных безопасных отступов. BitrixUI используется как источник решений и примеров; его рабочий код не изменяется.

## Исходное состояние и порядок работы

- В рабочем дереве уже есть изменения мобильных отступов, парсера, контрактных примеров и `notes-testing/book-club.md`. Они сохраняются; этот план не означает разрешение перезаписать их.
- Первый коммит содержит только план и аудит. После него реализация идёт по этапам ниже.
- Выполненные подпункты отмечаются `[x]` после проверки. В журнале указываются результат, проверки и ограничения.
- Код и пользовательский справочник обновляются вместе. Последний коммит содержит реализацию, проверки и итоговый статус плана.
- Публикация, push, production BitrixUI и изменение схемы CRM в задачу не входят.

## Этап 1. Сверка сумм и контракт грамматики (пункты аудита 1 и 5)

- [ ] Выделить проверяемую функцию расчёта состояния футера: рассчитанная сумма, объявленные подытоги, общий итог, разница с точностью до копейки.
- [ ] Использовать `comparisonTotal` для секций с объявленным итогом без отдельных цен; не считать их ошибкой.
- [ ] Сохранить реальное расхождение, в том числе цену `0`, несколько секций и общий итог.
- [ ] Добавить контрактные случаи: итог без цен, смешанные секции, количество вместо денег, цена за единицу, исходник эскиза после итога, общий итог без двойного счёта.
- [ ] Добавить запуск сравнения с локальным парсером BitrixUI по явно указанному пути. Расхождение известных неподдерживаемых конструкций должно сообщаться отдельно, а не менять наш парсер ради старой реализации.
- [ ] Проверить единый номер версии грамматики и документировать фактическую совместимость, включая известное расхождение общего итога.

Готовность: `Разом: 3072 грн` без отдельных цен не даёт ложное −3072; две секции 100 и 200 с общим итогом дают 300, а не 600; настоящая ошибка в 0,01 грн заметна.

## Этап 2. Редактор: активная строка, Enter, выделение, IME (пункт 2)

- [ ] Разделить обновление модели/суммы и перерисовку редактируемого DOM. Не заменять весь `innerHTML` во время обычного ввода.
- [ ] Отложить обновление оформления активной строки до ухода каретки на другую строку или blur. Сохранить позицию и выделение; не вмешиваться в IME-композицию.
- [ ] Сделать редактируемые строки чекбоксов и предупреждений блочными, оставив иконки инлайновыми.
- [ ] Проверить Enter, удаление, вставку нескольких строк, переключение заметки и режима, вставку из тулбара и slash-меню, чекбокс, undo/redo.
- [ ] Перед переходом к другой заметке/операцией над текстом получать актуальное содержимое редактора без ожидания debounce.

Готовность: ввод не вызывает постоянной перерисовки/скачков каретки; Enter в `[ ]`, `!`, `!!` создаёт новую строку; вводимые через IME символы не теряются.

## Этап 3. Диагностика с переходом к строке (пункт 3)

- [ ] Подключить возвращаемые парсером диагностики к интерфейсу; ошибки раньше предупреждений, без дублирования сообщений.
- [ ] Добавить компактную сводку и раскрываемые подробности вне мобильного футера.
- [ ] По нажатию открыть подходящий редактор, прокрутить и установить каретку на проблемной строке.
- [ ] Добавить RU/UK/EN подписи оболочки; сообщения парсера отображать безопасным текстом.
- [ ] Проверить пустой/исправный документ, несколько ошибок, незакрытый блок и общий итог.

Готовность: автор видит конкретную проблему и может сразу перейти к месту исправления; длинные сообщения не закрывают заметку на телефоне.

## Этап 4. Локальная библиотека шаблонов (пункт 4)

- [ ] Создать независимую модель библиотеки: версии формата, разделы, шаблоны, порядок, устойчивые ID, проверка структуры при загрузке.
- [ ] Хранить библиотеку в AppData отдельно от заметок; чтение/запись через существующий Tauri FS, с обработкой ошибок и сохранением пользовательских данных.
- [ ] Создать стартовые редактируемые заготовки «Изделие», «Визитки», «Наклейки», «Листовки», «Буклет» с диагностируемыми заполнителями.
- [ ] Сделать поиск по имени/пути, переход внутрь раздела и назад, предпросмотр через наш парсер, вставку в текущую позицию/замену выделения.
- [ ] Добавить сохранение выделенного фрагмента или всей заметки как шаблона; предложить название из первой содержательной строки.
- [ ] Добавить создание/переименование разделов, правку/переименование/перемещение шаблонов и удаление с подтверждением. Не удалять непустой раздел молча.
- [ ] Поддержать мышь, телефон и клавиатуру: Escape, стрелки, Enter, поиск, Ctrl/Cmd+Shift+Space; сохранить выделение до открытия меню.
- [ ] Добавить RU/UK/EN и адаптивное окно с безопасными отступами, доступными полями и кнопками.

Готовность: библиотека переживает перезапуск, работает без сети, шаблоны не появляются среди рабочих заметок, предпросмотр совпадает с результатом вставки.

## Этап 5. Оформление Т.З. (пункт 6)

- [ ] Добавить выбираемый пресет «Т.З.» рядом с существующим обычным/документным видом и сохранять настройку.
- [ ] Использовать местные токены: H1 с подчёркиванием, читаемая иерархия H2/H3, компактные предупреждения и табличные цифры в суммах/счётчиках.
- [ ] Сохранить уже перенесённые карточки изделий, сетку параметров, эскизы и одноколоночный вид на узком экране.
- [ ] Проверить светлую/тёмную тему, размеры шрифта и мобильные верхние/нижние отступы.

Готовность: производственное Т.З. удобнее читать, текст на телефоне не уменьшается ради плотности; существующий пресет «Документ» доступен.

## Этап 6. Редактирование без видимых маркеров (пункт 7)

- [ ] Добавить переключатель «Без маркеров» в режиме редактирования, используя тот же исходник и редактор.
- [ ] Скрывать только отдельные синтаксические маркеры; сохранять их в модели и копируемом исходнике.
- [ ] Сохранить режим для заметки; при переходе между исходником, симбиозом, чистым редактированием и просмотром не терять текст.
- [ ] Проверить выделение, ввод, удаление, вставку шаблона, восстановление каретки и скрытые блоки. Скрытые блоки должны оставаться доступными автору.
- [ ] Чётко описать границы: это текстовый редактор со скрытыми маркерами, а не импорт/редактирование произвольного HTML.

Готовность: автор редактирует форматированный текст, возвращается к разметке и получает те же маркеры/значения.

## Этап 7. Очистка HTML (пункт 8)

- [ ] Подключить DOMPurify как закреплённую зависимость и локальный ES-модуль для приложения без бандлера. Не загружать код с CDN.
- [ ] Обеспечить воспроизводимое обновление vendor-файла и сохранить лицензию.
- [ ] Направить HTML документа, построчного редактора и предпросмотра шаблона через одну функцию очистки.
- [ ] Оставить необходимые SVG, ссылки с безопасными протоколами, `data-line`, `data-toggle`, `contenteditable=false` и семантическую структуру; убрать обработчики событий/опасные элементы и URL.
- [ ] Проверить злонамеренный ввод и сохранность эскизов, чекбоксов, таблиц, скрытых блоков и подсветки редактора.

Готовность: нет внешней загрузки зависимости; очистка не ломает навигацию к строке, значки или SVG.
