# Noteriv → Notatnyk: что перенять (анализ)

Дата: 21.07.2026. Разбор проекта **Noteriv** (`/Volumes/Main/notervim/Noteriv`) —
популярный опен-сорс markdown-редактор с сильным UI/UX — и что из него дёшево и
быстро применимо у нас **без потери основной задачи** Notatnyk: _смета услуг →
заказ в 3 клика_ (см. [`../README.md`](../README.md)). Лицензия Noteriv — MIT
(© Jace), т.е. идеи и даже фрагменты кода переиспользуемы с указанием авторства
(совместимо с нашей AGPL-3.0).

## Главный вывод (сразу)

Noteriv — это **Obsidian-класс PKM-редактор** (граф, wiki-ссылки, теги, хранилища,
плагины, mermaid/KaTeX) на **CodeMirror 6 + React 19 + Next.js**, десктоп ~15 МБ.
Notatnyk — **узкий инструмент сметчика** на ванильном JS без бандлера, движок в
одном файле (`src/parser.js`), запуск мгновенный.

Отсюда честный вывод о переносимости: **их код напрямую не берём.** Живой
предпросмотр у них — это декорации/виджеты CodeMirror 6; чтобы это «переиспользовать»,
пришлось бы затащить CM6 + React + бандлер и убить главное наше преимущество —
лёгкость (память проекта: _keep it lightweight_). Поэтому берём **паттерны UX и
мелкие самодостаточные идеи**, реализуемые в нашем стеке за часы, а не архитектуру.

## Сравнение по осям

| Ось | Noteriv | Notatnyk | Кто впереди |
|---|---|---|---|
| Живой предпросмотр | CM6 inline-декорации (WYSIWYG) | симбиоз-режим (contenteditable + подсветка) | Noteriv по зрелости; концепт у нас тот же |
| Расчёты/деньги | нет (обычный markdown) | Σ, `Итого`-сверка, формулы, переменные, `[депозит]/[оплата]` | **Notatnyk** (это наша суть) |
| Экспорт клиенту | Publish/PDF | самодостаточный `.html` с кнопками «Принять/Оплатить» | **Notatnyk** (это наша суть) |
| Быстрая вставка | slash `/`-меню, автокомплит | панель кнопок + подменю | Noteriv (быстрее в потоке письма) |
| Навигация по документу | Outline (TOC), Quick open, поиск | поиск + свёртка секций | Noteriv |
| Полировка вида | дизайн-токены, Inter+mono, тени, скроллбары | добротно, но проще | Noteriv |
| Вес/скорость/простота | тяжёлый стек | ванилла, мгновенно | **Notatnyk** |
| PKM (граф/теги/вики) | много | нет и **не нужно** | — (вне нашей миссии) |

## Что у них сделано хорошо (и релевантно нам)

1. **Slash-команды (`/`-меню).** Печатаешь `/` — выпадает список блоков с иконкой и
   описанием, Enter вставляет. Быстрее, чем тянуться к тулбару. Реализация простая
   по идее: триггер-символ → список → вставка строки-шаблона.
2. **Per-file view mode.** Режим (Live/Source/View) запоминается **на каждый файл**
   (ПКМ в редакторе). Мелочь, но приятная: у разных заметок разный дефолт.
3. **Дизайн-токены и визуальная полировка.** Единый набор переменных (палитра
   Catppuccin), UI-шрифт Inter + моно для исходника, аккуратные тени, скруглённые
   тултипы, стилизованные скроллбары. Дёшево, а «дорого выглядит».
4. **Outline-панель (оглавление из заголовков)** + Quick open (fuzzy). Быстрый
   прыжок по длинному документу.
5. **Focus mode** (`Ctrl+Shift+D`) — гасит все строки, кроме активной. Дёшево
   (одна CSS-логика), помогает при письме.
6. **Формат-тулбар как отдельный дисциплинированный список** (`FormattingToolbar.tsx`)
   — данные-массив `{action,label,shortcut,content}` рендерятся в кнопки. У нас
   похоже, но их модель `onMouseDown → preventDefault` (не терять фокус/каретку)
   — полезная деталь.

## Что берём — приоритет (impact на «смету→заказ» × дешевизна)

Отсортировано «сначала самое выгодное и лёгкое»:

1. **★ Визуальная полировка (0.5–1 день, высокий эффект).** Свести цвета в набор
   CSS-переменных, добавить моно-шрифт для исходника, аккуратные тени/скроллбары/
   тултипы. Прямо влияет на восприятие **экспортной сметы** как премиальной →
   работает на «клиент одобряет». Ничего не тянем в зависимости.
2. **★ Slash `/`-меню под НАШИ паттерны (1–2 дня).** Не «heading/quote», а то, что
   ускоряет смету: `= 0 грн`, `: 0 грн`, `Итого:`, `[4000 шт]`, `[депозит] = 30%`,
   `[оплата] = ` , таблица. Это буквально про «смету в 3 клика». Реализуемо
   ванильно поверх нашего `runInsert()` — берём готовый список из тулбара.
3. **Per-note view mode (0.5 дня).** У нас уже есть `setView()` и per-note-состояние
   (свёртки в localStorage) — до-персистить выбранный режим на заметку.
4. **Outline / прыжок по секциям (0.5–1 день).** `groupBlocks()` уже строит дерево
   секций — осталось показать его как список-оглавление с кликом-скроллом (у нас
   уже есть якоря `data-line`). Полезно для длинных смет.
5. **Focus mode (0.5 дня, опционально).** Дёшево, но эффект для сметчика скромный —
   берём в последнюю очередь.

## Что НЕ берём (осознанно — против миссии/лёгкости)

- **CodeMirror 6 / React / Next.js / бандлер.** Ломает лёгкость и мгновенный старт.
  Наш симбиоз-редактор уже закрывает 80% ценности «живого предпросмотра».
- **PKM-обвязка:** граф-вью, wiki-ссылки `[[]]`, backlinks, теги, vaults, daily
  notes, flashcards, canvas/рисование, slides, board/calendar/dataview. Всё это —
  чужая задача (второй мозг), а не «довести смету до оплаты». Разбавит продукт.
- **mermaid / KaTeX / PDF-viewer / plugin API.** Тяжёлые зависимости ради сценариев,
  которых нет у сметчика услуг.

> Правило фильтра при заимствовании: «Помогает ли это быстрее **сделать смету** или
> быстрее **получить согласие/оплату**?» Если нет — мимо, даже если красиво.

## Часть 2: фронтенд-стили и подходы (берём; React — нет)

Их UI держится на **CSS-переменных + `color-mix()`**, а не на React. Значит переносимо
в наш ванильный `styles.css` почти целиком — это чистый CSS.

### Наша база уже хорошая — их палитру НЕ копируем
У нас уже есть токен-система: семантические переменные + светлая «бумажная» тема и
`[data-theme="dark"]` (`src/styles.css:1`). Для клиентской сметы это **лучше**, чем их
Catppuccin: цветные по уровню заголовки (h1-синий/h2-сиреневый/h3-зелёный) выглядят как
редактор кода, а не как счёт. Берём их **приёмы**, палитру-профессионализм оставляем свою.

### Приём №0 (фундамент): `color-mix()` вместо кучи под-переменных
У них все состояния (hover, выделение, тинт callout) выводятся из базового токена:
`background: color-mix(in srgb, var(--accent) 12%, transparent)`. Это убирает десятки
ручных `--x-hover`/`--x-tint` и держит гамму согласованной. Наш webview
(WKWebView / WebView2 / Android WebView — свежие WebKit/Chromium) это поддерживает.
⚠️ **В экспортном `.html` — НЕ применять:** он открывается в браузере **клиента** (может быть
старый Safari/Chrome). Там — только явные цвета. То есть `color-mix` — во внутреннем UI,
экспорт остаётся консервативным.

### Конкретные паттерны к переносу
| Паттерн у Noteriv | Что даёт | Куда у нас | Стоимость |
|---|---|---|---|
| Callout: `border-left:4px` + `color-mix 8%` фон + скруглённые углы (шапка/низ) | аккуратные выноски с цветокодом по типу | наши `!`/`!!` (цвета уже есть) — обновить форму | низкая |
| Segmented control: инсет-фон + активная кнопка с тенью-кольцом `0 1px 3px, 0 0 0 1px` | «дорогой» переключатель | вид-тоггл source/симбиоз/рендер и размер шрифта S/M/L | низкая |
| Floating-панель: `backdrop-filter: blur(12px)` + слоёная тень + волосяная рамка | премиальные всплывашки | диалоги (шрифт, таблица, настройки, шпаргалка `?`) → единый стиль | низкая |
| Icon-chip: 28px скруглённый квадрат с иконкой, тинт на hover/active | читаемые пункты меню | слэш-меню и подменю тулбара | низкая |
| Rendered-типографика: blockquote (лев. бордер + тинт + радиус), `code`-чип, `th`-фон, `accent-color` у чекбоксов, цветной `li::marker` | чище рендер | наш рендер **И экспорт-смета** | низкая–средняя |
| Тонкие скроллбары (4–8px, прозрачный трек), `transition .12–.15s`, шкала радиусов 6/8/10 | микрополировка | глобально | низкая |

### Дополнительные подходы (сверх CSS)
- **Командная палитра / Quick-open `Ctrl+K`** — fuzzy-прыжок к смете. Поиск уже есть; палитра — про скорость «в 3 клика». Средняя стоимость.
- **Data-driven действия + горячие клавиши** — у них массив `{action,label,shortcut}`. Мы так уже делаем для тулбара; расширить на клавиши (`Ctrl+B/K/…`). Средняя.
- **`onMouseDown → preventDefault` на кнопках вставки** — не терять каретку/выделение. Мелочь, но правильная.
- **Frameless-титлбар** (`-webkit-app-region: drag` + свои кнопки окна) — нативно-премиальный вид, но больше возни и ОС-нюансов → **стретч**.

«бумага» лучше под счёт-смету. Дальше — перенос мобильных стилей/юзабилити (см. отдельную секцию).
