# План разработки: «Память расчётов» → $2 000+/мес

> Продукт: заметка-калькуляция, которая **помнит, что ты кому считал**.
> Петля: **Шаблон → Расчёт → @Клиент → История**.
> Цель монетизации: $2 000+/мес — базовый минимум, горизонт 3 месяца от старта Этапа 1.
> Принципы (нерушимы): лёгкость, `.md`-first, локальные данные, никакого CRM-раздувания.

Статус-легенда: `[ ]` не начато · `[~]` в работе · `[x]` готово

## Этап 1 (неделя 1): История версий

Боль: «клиент вернулся — а что я ему называл?» / «дописал, испортил, верни как было».

### 1.1. Хранилище снимков
- [ ] Папка `.history/` рядом с заметками (создавать лениво при первом снимке, `mkdir` через plugin:fs).
- [ ] Один файл на заметку: `.history/<id>.jsonl`; строка = снимок:
  `{"ts": 1789000000000, "hash": "a3f19c", "label": null, "body": "<весь текст>"}`
- [ ] **Полные снимки, не диффы.** Заметка — килобайты; 20 снимков ≈ 100 КБ. Простота дороже байтов.
- [ ] Кольцевой буфер: лимит `HISTORY_LIMIT` (free 5 / pro 20). При превышении удаляем самые старые **неименованные**; именованные (`label != null`, только Pro) не вытесняются, но входят в лимит Pro.
- [ ] Хеш — быстрый строковый (djb2/fnv в 10 строк JS, без крипты): нужен только для дедупликации «текст не менялся — снимок не пишем».

### 1.2. Триггеры снимка
- [ ] При закрытии заметки (переключение на другую) — если hash изменился с последнего снимка.
- [ ] Во время долгой правки — не чаще 1 снимка / 10 мин (таймер в `persist()`).
- [ ] Перед восстановлением версии — автоснимок текущего состояния (откат обратим).
- [ ] Перед удалением заметки — финальный снимок (страховка от «ой»).

### 1.3. UI версий
- [ ] Кнопка `⏱` в `.bar-right` → панель версий (переиспользовать паттерн `.cheat`-модалки).
- [ ] Строка версии: `16.07 14:23 · Итого: 54 980 грн` — итог тянуть быстрым `render()` тела снимка (движок уже отдаёт `stats.total`).
- [ ] Тап по версии → превью рендера (read-only) → кнопки «Восстановить» / «Закрыть».
- [ ] Pro: длинный тап/иконка ✏ → задать `label` («вариант для Иванова»).
- [ ] Free и лимит исчерпан: старые версии в списке видны серым с замком 🔒 → тап ведёт на paywall-экран (§4). Данные не удаляем — они «заморожены», это честнее и продаёт лучше.

### 1.4. Критерии приёмки
- Правил заметку 30 минут → в истории ≤ 4 снимков, не 200.
- Восстановил v-3 → текущий текст не потерян (есть в истории).
- Синк папки через Dropbox не ломает `.jsonl` (append-only, конфликт = дубль файла, не потеря).
- `node --check` чист; рендер заметки 500 строк < 50 мс (история не трогает hot-path).

## Этап 2 (неделя 2): Шаблоны

Боль: «10 расчётов в день — каждый раз собирать смету заново».

### 2.1. Модель
- [ ] Шаблон = обычная заметка с `#шаблон` (`#template` / `#шаблон` — ключевое слово в `LOCALE.templateTag`, локализуемо). Никакой отдельной сущности/папки — ноль новых форматов.
- [ ] Заметки-шаблоны в списке помечаются значком ▤ и собираются в секцию «Шаблоны» сверху списка (сортировка по частоте использования — счётчик в `config.json`).

### 2.2. Плейсхолдеры вводных
- [ ] Синтаксис: `[имя] = ?` — переменная без значения. Рендер: жёлтый чип «заполни меня», строка не считается, Σ показывает «…».
- [ ] Расширение: `[имя] = ? 4000` — с дефолтом (рендер считает по дефолту, чип остаётся подсвеченным, пока не заменён).
- [ ] `parser.js`: `RE_VARDEF` уже ловит строку — добавить ветку `rhs === '?' | '? число'`.

### 2.3. Поток «Новый из шаблона»
- [ ] Кнопка `＋` → если есть шаблоны, меню: «Пустая» / список шаблонов.
- [ ] Создание: дубль тела без строки `#шаблон`, заголовок `<Название> — <дата>`, курсор на первом `?`.
- [ ] **Tab-навигация**: Tab прыгает к следующему `[x] = ?`, выделяя `?` (готово к вводу с клавиатуры/цифроблока). Реализация — по образцу `expandDateAtCursor()` в `main.js`.
- [ ] Целевой хронометраж: шаблон из 5 вводных → готовый расчёт **≤ 60 секунд**. Это метрика, мерить руками на телефоне.

### 2.4. Стартовые шаблоны (контент, не код)
- [ ] 6 шаблонов × 3 языка: фриланс (час×ставка), дизайн-пакет, полиграфия, ремонт (м²), фото-съёмка, аренда. Раскладываются при первом запуске (как текущая demo-заметка), помечены `#шаблон`.
- [ ] Каждый шаблон обязан содержать: 3–5 `? `-вводных, один `/* себестоимость */`-блок, `> @клиент`-карточку, `Итого` — чтобы шаблон сам обучал всем фичам.

### 2.5. Критерии приёмки
- Новый пользователь без чтения доков делает первый расчёт из шаблона ≤ 2 мин.
- Tab работает на Android (виртуальная клавиатура: кнопка «→» в тулбаре дублирует Tab).

## Этап 3 (неделя 3): @Клиенты — лента без CRM

Боль-заголовок продукта: «что я считал этому клиенту?»

### 3.1. Индекс
- [ ] `render()` дополнительно возвращает `clients: ['Иванов', …]` — все `@имена` из карточек `> @Имя` (+ инлайн-упоминания `@имя` в тексте, если решим — отдельный флаг).
- [ ] `main.js` держит карту `клиент → [{noteId, updated, total}]`, пересобирается при загрузке и `persist()` (дёшево: данные уже в памяти).

### 3.2. UI
- [ ] Под поиском — горизонтальная лента чипов: `@Иванов (12) @ТОВ_Альфа (3)…`, сортировка по последней активности.
- [ ] Тап по чипу → список фильтруется: только расчёты клиента, хронологически, у каждого — дата+время и итог. Это **киллер-экран**, он должен открываться из холодного старта приложения ≤ 2 тапа.
- [ ] Поиск и чип комбинируются (`@Иванов` + «визитки»).
- [ ] Free: лента клиента показывает 30 последних дней, глубже — 🔒 paywall. Pro: вся история.

### 3.3. Критерии приёмки
- «Подними цену для Иванова от февраля» — от иконки приложения до нужной цифры ≤ 10 секунд.
- 300 заметок, 40 клиентов: фильтр без лагов (индекс в памяти, без чтения файлов).

### 4.2. Paywall-экран

### 4.3. Витрина
- [ ] Лендинг (1 страница, статика): заголовок «Помнит, что ты кому считал», 30-сек видео (телефон: клиент вернулся → тап @имя → цена от 12 февраля), кнопка покупки, FAQ.

### 4.4. Гейты (по итогам месяца витрины)

- 5–24 — продукт жив, месседж кривой: A/B заголовка лендинга, новые видео.

## Этап М (параллельно 1–4): Мобильная адаптивная вёрстка

Сценарий «10 расчётов в день» живёт в кармане. Android-сборка есть; вёрстку доводим до «телефон — первичное устройство», а не «десктоп, сжатый в 360px».

### М.1. Каркас
- [ ] Брейкпоинты: **≤640px** телефон (уже есть, дорабатываем), **641–1024px** планшет/сплит-скрин (новый: сайдбар сжимается до 64px иконок), **>1024px** десктоп (как есть).
- [ ] Телефон: режим по умолчанию — **«Только заметка»** (рендер), редактор — по кнопке; вертикальный сплит двух панелей на 360×640 нечитаем. Текущий `.split{flex-direction:column}` заменить на переключение панелей.
- [ ] Нижняя навигация (телефон): `[☰ список] [✎/▤ редактор⇄рендер] [⏱ версии] [＋ новый]` — большой палец не тянется к верхней панели. Верхний `.bar` на телефоне сворачивается до заголовка+Σ.
- [ ] Safe-area: `padding: env(safe-area-inset-*)` для нижней навигации и шторки (вырезы, жестовая полоса Android/iOS).

### М.2. Тач-эргономика
- [ ] Все интерактивные цели ≥ **44×44px**: чекбоксы рендера (сейчас 20px бокс — увеличить зону тапа через padding), чипы клиентов, кнопки версий, `.tb-btn` тулбара.
- [ ] Тулбар редактора: на телефоне — одна строка с горизонтальным скроллом (`overflow-x:auto`, без переноса), приоритетные кнопки первыми: `? [имя]=`, `= грн`, Tab-стрелка, `//`, шаблон таблицы.
- [ ] Свайпы: список ← → закрыть шторку; строка заметки — свайп влево = удалить (с undo-снэком, не confirm).
- [ ] Длинный тап по заметке в списке → контекст: дублировать / сделать шаблоном / удалить.

### М.3. Клавиатура и ввод
- [ ] `textarea#src`: `font-size ≥ 16px` на телефоне (iOS-зум при фокусе), `inputmode` не трогаем (нужны буквы+цифры).
- [ ] При открытой клавиатуре: нижняя навигация скрывается (`visualViewport.onresize`), тулбар прилипает над клавиатурой — кнопки `?`/Tab-стрелка/`= грн` доступны без слепого набора символов.
- [ ] Tab-прыжки по `? `-вводным обязаны работать с виртуальной клавиатуры (кнопка «→» в тулбаре).

### М.4. Рендер на узком экране
- [ ] Таблицы `.r-table`: горизонтальный скролл в собственном контейнере (`overflow-x:auto`), страница не скроллится вбок никогда.
- [ ] `.r-total`, футер Σ: не переносить критичные числа; длинные разбивки секций — в две строки.
- [ ] Карточка `> @клиент` и чипы цен: проверить на 320px (минимальная ширина поддержки).
- [ ] Панель версий и paywall — полноэкранные шторки снизу (bottom-sheet), не центр-модалки.

### М.5. Тест-матрица (прогонять на каждом этапе)
| Устройство | Что проверяем |
|---|---|
| Android 360×640 (реальный, дешёвый) | весь флоу «шаблон → расчёт → шаринг» пальцем |
| Android + клавиатура открыта | тулбар над клавиатурой, Tab-прыжки |
| Планшет 768px / сплит-скрин | иконочный сайдбар, две панели |
| Десктоп узкое окно 500px | деградация без поломок |
| Тёмная тема на всех вышеперечисленных | контрасты чипов/карточек |

## Этап О (после Этапа 4, опционально): Варианты оформления

Два пресета вёрстки рендера — дифференциация «смета выглядит как документ, а не как заметка». Реализация: класс на `#out` + блок CSS-переменных; движок не трогаем.

- [ ] **«Рабочий»** (текущий вид) — плотный, для себя.
- [ ] **«Документ»** — шрифт с засечками для заголовков, больше воздуха, итоги крупнее, скрытая структура: то, что уходит клиенту (скриншот/печать/будущий экспорт). Сюда же print-CSS (`@media print`): чистые поля, без UI.
- [ ] Переключатель в баре рендера; выбранный стиль запоминается per-note (строка в `config.json`).
- [ ] Pro-граница: «Рабочий» бесплатно, «Документ» — Pro (это экспортная ценность).

## Метрики (смотрим еженедельно)
1. Активация: % новых, сделавших расчёт из шаблона в день 1.
2. Ядро: расчётов/пользователя/неделю (гипотеза боли = «10 в день» — проверяем!).
3. Касания paywall → покупка (цель ≥ 5%).
4. $ MRR-эквивалент: lifetime/3 + подписки. Цель месяца 3: $2 000.

## Риски
1. **Телефон — первичен**, а разработка идёт на десктопе → тест-матрица М.5 обязательна в каждом этапе, не в конце.
2. Синтаксис пугает нетехнарей → пользователь никогда не начинает с пустого листа (шаблоны при первом запуске).
3. Дистрибуция важнее кода → видео и лендинг — «фичи» Этапа 4 с полноценным бюджетом времени.
4. Dropbox-конфликты `.jsonl` → append-only формат, конфликт-копии не теряют данные.
